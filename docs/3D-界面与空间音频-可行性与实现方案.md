## 0. 先看结论（TL;DR）

| 问题 | 结论 | 一句话依据 |
|---|---|---|
| 2D 图谱能改成 3D 吗？ | **能**，成本中等（UI 约 2.5–3.5 人日） | UI 是自绘 SVG，没有 3D 引擎负担；≤32 个节点用手写 Canvas 2D 透视投影就够，不需要 Three.js/WebGL |
| 能做空间音频吗？ | **能，但必须在 C++ 混音线程里做**，不能在渲染层做 | 音频 PCM 只存在于 `audiohub-hub.exe` 进程内，渲染进程从头到尾拿不到采样数据（`ui/` 全目录无 Web Audio/WebGL 代码） |
| 有没有硬阻塞？ | **没有**。有 6 个条件/边界（见 §1.4）；Android 端已在 v1.4 落地（见 §8，未真机验收） | 全部可解，代价与影响见 §4 |
| 能达到什么效果？ | 左右方位准确、距离可听、前后为"弱线索"；**不是 HRTF**，不承诺闭眼分辨前后 | 双耳线索只有 ILD/ITD/距离/后向低通；实测后向 10 kHz 内容 -11.1 dB（§2.3） |
| 工作量 | 引擎 1.5–2 人日（草稿已跑通）+ UI 2.5–3.5 人日 + 联调 0.5–1 人日 + Android 3–5 人日（v1.4 已做） | 引擎 13 个单测已全过；UI 投影/拾取/听者数学 23/23 断言已过；Android 空间化 23179 断言、黄金值 455 项通过 |

> **实施状态（2026-10-27 00:20）**：P0 已落地并完成 **v1.3 物理房间修订**，**v1.4 Android 端** 已落地并交叉验证（工作区改动未提交）：单测 **78 例 / 10830 断言全绿**，`node tools\ui-e2e.js` **29/29 PASS**（exit 0）；Android `run-spatial-check.ps1` **23179 断言 PASS**、`run-scene-check.ps1` **410 checks PASS**、Lead 独立黄金值 **455 项 PASS**。偏差、落地文件与未验证项见 §6 / §8，v1.3 详见 §7。

**一句话方案**：把 `ui/#graph` 的 SVG 换成"手写 Canvas 2D 透视投影"的 3D 场景（零新依赖），在物理房间中按"黄金角 + 远近分层"摆放节点（球体近大远小），听者固定在房间中心朝屏幕上方；**UI 作为位置的唯一权威**，用两条新增 IPC/HTTP 把"听者位姿 + 每源坐标"按 ≤20 Hz 推给内核；内核在 `MixerLoop` 里对每路音频做"单声道化 → 等功率声像 → 距离衰减 → 后向增益/低通 → 双耳 ITD"；位置缺失、旧版内核、每源旁路时自动回退到当前混音路径。

### 1.2 3D 界面：可实现（成本中等）

| # | 原因 |
|---|---|
| 1 | **数据模型和交互信息都够用**：图谱节点、在线状态、电平、本机/汇聚端/离线角标、链路方向、切换汇聚端、音量面板，全部来自现有 `graph`/`state`，不需要改协议（`apps/hub_main.cpp:113-193`、`:268-361`）。 |
| 2 | **布局可平移**：旧版圆环公式 `θ_i=-π/2+i·2π/n` 直接复用，把屏幕坐标换成世界 `XZ` 平面即可；已在原型中数值验证（§2.2）。 |
| 3 | **不存在渲染技术门槛**：节点上限 32，场景 = ≤32 球 + ≤31 线段 + 文字，手写 Canvas 2D 透视投影完全够；原型已跑通投影/深度/拾取/拖动数学（23/23 断言，§2.2/§2.5）。 |
| 4 | **不引入依赖**：不需要 Three.js/WebGL，符合"单 exe、便携、无构建链"的项目风格；也规避了 `--disable-gpu` 下 WebGL 走软件光栅的不稳定性。对比见 §2.1。 |
| 5 | **真正的成本不在 3D 数学**：而在拾取/拖动手势、标签避让、多节点遮挡、e2e 从 DOM 选择器迁移到坐标点击（`tools/ui-e2e.js:194-236`），以及视觉打磨。 |

> 结论：**3D 界面可做，属"改渲染层 + 加相机交互"，不动数据与协议。**

### 1.3 空间音频：有条件可实现

四个必要条件，缺一不可：

| # | 条件 | 为什么（证据） |
|---|---|---|
| C1 | **空间化必须做在 C++ 混音线程（`MixerLoop`）** | 音频只在 hub 子进程内：UDP 收包 → 抖动缓冲 → ASRC → `MixBlock` → WASAPI（`src/hub_core.cpp:917-1051`）。Electron 渲染进程拿不到 PCM，也没有任何音频节点（`ui/` 全目录无 `AudioContext`/`PannerNode`/`<audio>`）。 |
| C2 | **只能用双耳线索（ILD + ITD + 距离 + 弱后向滤波）**，P0 不做 HRTF 卷积 | 输出是普通立体声设备（48 kHz/2ch，`platform/win/wasapi_audio.hpp:12`）。只需在 L/R 两耳上做增益差、时差、距离与后向低通，即可获得可用的左右/距离/前后弱线索。HRTF 需要 HRIR 卷积，属 P1。 |
| C3 | **需要一条新的控制通道**（UI → 内核） | 内核当前不知道任何位置（协议无坐标）；必须新增 `POST /api/listener`、`POST /api/source/spatial` 与两条 IPC（§2.4）。 |
| C4 | **只在"Windows 端是汇聚端"时生效**；Android 当 hub 时 P1 | Android 没有 HTTP 服务（`android/` 全目录无 `HttpServer/ServerSocket/NanoHTTPD`），PC 无法把位姿推给手机 hub；且 Android 混音在 `ReceiverService.java:259-346` 里另有一套实现。 |

替代路线（"把 Web Audio 的 PannerNode 用在渲染层"）**不推荐**，代价量化如下：
- 需要把 PCM 从 C++ 子进程送到渲染进程：48 kHz×2ch×16bit = 192 KB/s/流，32 路峰值 ≈6 MB/s，且需自建进程间音频通道与双缓冲；
- UI 将变成"播放端"，要重做抖动缓冲/时钟对齐/设备切换，跨进程延迟至少 +10–20 ms，还会与 hub 的声卡时钟产生漂移问题；
- 破坏"UI 只做控制面、音频只在 hub"的既有架构（`ui/main.js` 的设计前提，`:307-330` 只收发 JSON）。
一句话：**为了用 PannerNode 而重做音频链路，收益（HRTF）与成本不成比例；P0 用内核空间化，P1 若确有 HRTF 需求再单独立项。**

### 1.4 明确的阻塞点与边界（不粉饰）

| # | 阻塞/边界 | 性质 | 处理 |
|---|---|---|---|
| B1 | 渲染层拿不到 PCM | **硬约束**（不改架构绕不过） | 空间化放内核（C1） |
| B2 | 位置不在 GRAPH 协议内 | 工作量，不是阻塞 | 新增 UI→核心本地控制通道；坐标**不进**图谱协议（§4.3、附录 B） |

## 2. 第 2 部分：实现方案（分步）

### 2.0 目标数据流

```
┌────────────────────────── Electron 渲染进程（UI） ──────────────────────────┐
│  scene3d.js：相机(φ,dist,pitch) → project/unproject/hitTest/拖动              │
│  位置权威：派生布局（旧 θ 公式）+ 手工 pin（localStorage）                    │
│  上报泵（50 ms tick，变化才发，≤20 Hz，2 s 心跳，in-flight 背压）             │
└───────────────┬──────────────────────────────────────────────────────────────┘
                │ preload.js: window.hub.setListener / setSourceSpatial（窄接口）
                ▼
┌────────────────────────── Electron 主进程 ──────────────────────────────────┐
│  ipcMain.handle('hub:setListener' / 'hub:setSourceSpatial')                 │
│  → httpRequest → 127.0.0.1:4780（JSON，失败静默）                            │
└───────────────┬──────────────────────────────────────────────────────────────┘
                ▼
┌──────────────────── audiohub-hub.exe（C++ 内核） ───────────────────────────┐
│  hub_main.cpp 新增路由 /api/listener、/api/source/spatial                    │
│  → HubCore::SetListenerPose / SetSourceSpatial（Impl::mutex 保护）           │
│                                                                              │
│  MixerLoop（每 5 ms，持 mutex）：每流 block_buffer（48k/2ch/240 帧）          │
│    ├─ 有位置且启用 → SpatialState::Process：单声道化 → 等功率/距离/后向/ITD   │
│    └─ 无位置/旁路/旧路径 → 原样，MixInput.gain=s.gain                        │
│  → MixBlock（各源相加）→ master → SoftLimit(0.85) → output_ring → WASAPI     │
└──────────────────────────────────────────────────────────────────────────────┘
```

**职责边界**：UI 唯一决定"声源在哪、听者朝哪"；内核只做"给定位置的渲染"，不猜测布局。位置没上报时，行为与当前版本逐样本一致（回退安全）。

### 2.1 步骤 1：3D 场景搭建

#### 2.1.1 渲染器选型

| 约束 | 证据 | 结论 |
|---|---|---|

#### 2.1.2 相机与投影（已由原型验证）

坐标系：右手系，+Y 向上，1 unit ≈ 1 m；`+X` = 听者右耳，`-Z` = 听者正前。相机绕原点球坐标 `(φ, dist, pitch)`，默认 `φ=0, d=2.6, h=0.72`（`pitch = asin(0.72/2.6)=16.07°`），看向原点；视场 `fovY=47.5°` → 焦距 `focalPx=(460/2)/tan(23.75°)=522.71`。

```js
// ui/scene3d.js —— 相机基与投影（纯函数；build/_plan/proto3d2.js 已验证）
const DEG = Math.PI / 180, WORLD_UP = [0, 1, 0]

function camera (phiDeg, dist, pitchDeg) {
  const d = dist == null ? CFG.camDist : dist
  const phi = phiDeg * DEG
  const p = pitchDeg == null ? Math.asin(Math.min(CFG.camH / d, 0.999)) : pitchDeg * DEG
  const eye = [d * Math.cos(p) * Math.sin(phi), d * Math.sin(p), d * Math.cos(p) * Math.cos(phi)]
  const fwd = norm(sub([0, 0, 0], eye))
  const right = norm(cross(fwd, WORLD_UP))      // φ=0 时 = +X（右耳）
  const up = cross(right, fwd)
  return { eye, fwd, right, up, phiDeg, dist: d, pitchDeg: p / DEG, focal: CFG.focalPx }
}

// 世界点 → 虚拟 920x460 屏幕坐标（投影原点沿用旧布局中心 (460,208)）
function project (view, p) {
  const rel = sub(p, view.eye)
  const depth = dot(rel, view.fwd)
  if (depth <= CFG.near) return { visible: false, depth }
  const k = view.focal / depth
  return { visible: true, sx: CFG.CX + k * dot(rel, view.right),
           sy: CFG.CY - k * dot(rel, view.up), depth, ppu: k }
}
```

`CFG`：`ringR=1.0, hubBallR=0.23, nodeBallR=0.145, fovYDeg=47.5, camH=0.72, camDist=2.6, zoomMin=0.7, zoomMax=1.6, dragRMin=0.3, dragRMax=2.0, VW=920, VH=460, CX=460, CY=208, near=0.05`。
其中 `hubBallR/nodeBallR` 由旧版 46 px/29 px 反解：`46×2.6/522.71≈0.229`、`29×2.6/522.71≈0.144`。

### 2.2 步骤 2：2D → 3D 坐标映射（设计期推导；实现已被 §7 物理房间取代）

旧公式（`ui/renderer.js:236-273`）：`θ_i=-π/2+i·2π/n`，`x=460+188·cosθ`，`y=208+188·sinθ·0.78`，按 id 升序 `i`。
3D 公式（同一 θ，去掉 0.78 压扁，交给透视投影）：

```
节点 i（n = 非 hub 节点数）：
  θ_i    = -π/2 + i·2π/n
  world  = (R·cosθ_i, 0, R·sinθ_i)      // R=1，全部 y=0（与声像平面一致）
  世界方位 az_i = θ_i + 90° = i·360°/n   // az=0 正前(-Z)，+90°=+X 右耳，180° 身后
```

n=8 时 `az = 0,45,…,315°`；node0 在屏幕上方（正前），顺时针到身后/左耳——与旧版视觉顺序完全一致（旧 node0 也在正上方）。环纵向从旧 293 px 缩到 **128.96 px**，深度感由"近大远小"（2.17×）承担。

> **v1.3 变更**：本节"等距圆环 + 交替分环"布局已由 §7 的物理房间槽位取代；实现中 `ringSpec/slot` 已删除，改为 `buildSlots`（黄金角槽位）+ `roomLayout`。

```js
// 布局核心（已验证：hub 恒原点、pin 优先、n=2..32 全可见）
function ringSpec (n) { return n <= 6 ? { rings: 1, gap: 0 } : n <= 16 ? { rings: 2, gap: 0.26 } : { rings: 3, gap: 0.21 } }

function slot (idx, n) {                       // idx = 按 id 升序的序号（collectGraph 已排序，renderer.js:160）
  const spec = ringSpec(n)
  const ring = spec.rings === 1 ? 0 : idx % spec.rings       // 交错分环，避免同角相邻
  const members = []
  for (let i = 0; i < n; i++) if ((spec.rings === 1 ? 0 : i % spec.rings) === ring) members.push(i)
  const j = members.indexOf(idx), m = members.length || 1
  const theta = (-90 + j * (360 / m) + (ring % 2 ? 180 / m : 0)) * DEG   // 旧角度公式 + 外环错半步
  const r = 1.0 + ring * spec.gap
  return { pos: [r * Math.cos(theta), 0, r * Math.sin(theta)], ring, azDeg: wrap360(theta / DEG + 90) }
}

function layout (nodes, pins) {                // nodes 含 isHub；pins: {id:[x,0,z]}
  const out = new Map()
  const hub = nodes.find(n => n.isHub)
  if (hub) out.set(hub.id, { pos: [0, 0, 0], ring: -1, pinned: false })
  nodes.filter(n => !n.isHub).forEach((n, i) => {
    const pin = pins && pins[n.id]
    out.set(n.id, pin && pin.length === 3 && pin.every(Number.isFinite)
      ? { pos: pin.slice(), ring: 0, pinned: true }
      : Object.assign({ pinned: false }, slot(i, nodes.length - 1)))
  })
  return out
}
```

**布局稳定性**（切换 hub / 节点进出时不乱跳）：
1. 派生布局**不持久化**：每次按"当前非 hub 节点按 id 升序"重算，确定性、可复现；
2. hub 永远在原点；旧 hub 回到自己"按 id 排序"的环位，新 hub 离开环位——角度只由排序序号决定，其他节点序号不变；
3. 环重排用 250 ms 位置插值（lerp）做动画，避免瞬移；
4. 手动 pin 优先，不参与环重排；双击节点 = 清除 pin 回到派生位置；
5. 持久化 `localStorage['audiohub.scene3d.v1'] = {v:1, cam:{yawDeg,dist}, pins:{[nodeId]:[x,0,z]}}`（实测 79 字节，≤2 KB）；只存 pin + 相机。

#### 2.2.1 拖动映射与"屏幕位置 = 声音方位"验收

```js
function unproject (view, sx, sy, planeY) {
  const dx = (sx - CFG.CX) / view.focal
  const dy = -(sy - CFG.CY) / view.focal
  const dir = norm(add(add(mul(view.right, dx), mul(view.up, dy)), view.fwd))
  if (Math.abs(dir[1]) < 1e-6) return null                    // 视线与地面平行（pitch=0 保护）

  return t <= 0 ? null : add(view.eye, mul(dir, t))           // t<=0：交点在相机后
}
```

### 2.3 步骤 3：音频空间化接入（C++ 内核）

#### 2.3.1 坐标系契约（UI 与 C++ 必须逐字一致）

```
右手系，+Y 向上，1 unit ≈ 1 m。听者 yaw=0 面朝 -Z：
forward = (-sin(yaw)cos(pitch),  sin(pitch), -cos(yaw)cos(pitch))
right   = ( cos(yaw),             0,          -sin(yaw))
up      = ( sin(yaw)sin(pitch),   cos(pitch),  cos(yaw)sin(pitch))   // = right × forward
azimuth = atan2(dot(rel, right), dot(rel, forward))                  // + = 右耳
```

- 默认场景：hub/听者在原点；其它节点 `x=R cosθ, z=R sinθ`（R=1）；相机在 +Z、距离 2.6R 俯视中心 → **屏幕上方=远处=听者正前(az=0)、屏幕右=+X=右耳(+90)、屏幕下方=+Z=身后(180)**。
- 相机 orbit：`yaw` 跟随相机；拉近/拉远**不改**听者位置（否则"缩放 = 整体变响"）。
- 与 UI 的换算：相机在 `(D sinφ, h, D cosφ)` 时 `yaw=φ`；节点世界方位 `a` → 相对听者 `az = a + φ`。数值已验证误差 2.8e-14（§2.5）。

#### 2.3.3 每源状态、ITD 实现与线程安全

| main | `ipcMain.handle('hub:setListener')`、`('hub:setSourceSpatial')`，参数夹紧 | 复用 `httpRequest`（`ui/main.js:307-330`）与 `hub:setSource` 的夹紧风格（`:458-470`） |
| 核心 | `POST /api/listener`、`POST /api/source/spatial` | 插在 `apps/hub_main.cpp:551` 兜底之前（实际 `:504-550`）；返回恒 200 + `{"ok":...}`（与现有路由一致） |

```json
POST /api/listener          {"x":0,"y":0,"z":0,"yaw":-32.5,"pitch":-16}
POST /api/source/spatial    {"nodeId":"192.168.1.11:47000","x":-0.71,"y":0,"z":0.71,"enabled":true}
```

- `nodeId` = 图谱节点 id（`<ip>:<audioPort>`，`apps/hub_main.cpp:177-190`），内核用现成 `NodeIpOf()`（`src/hub_core.cpp:74-77`）去掉端口按**设备 IP** 归并——一台设备重连后流 id 变了但 IP 不变，位置不丢。
- 校验：坐标 `[-20,20]`、yaw `[-180,180]`、pitch `[-90,90]`；HTTP 对越界 source 直接拒绝（`coord out of range`），listener 用 `std::clamp`，内核再校验一次（双保险）。
- 响应：`{"ok":true}`；缺字段 → `{"ok":false,"error":"need x/y/z"}`。

#### 2.4.2 发送频率与节流

| 数据 | 时机 | 频率/上限 | 载荷实测 |
|---|---|---|---|
| listener 位姿 | 相机 orbit 拖动中 | ≤20 Hz（50 ms tick，变化才发；静止 2 s 心跳） | 44 B → 0.88 KB/s |
| 每源位置 | 拖拽结束、首次进入 3D、布局重排、`streamId` 从 0 变非 0 | **变化才发**，32 节点最多 32 次爆发，静止 0 B/s | 71 B/源（≈1.4 KB/s @20 Hz 单源变化） |

选择说明：引擎侧建议 10 Hz 也够（50 ms 平滑会抹平台阶）；UI 取 **20 Hz 上限**以保留拖拽跟手感，单次请求 <100 B，本地 loopback 成本可忽略。若低端机实测有压力，把 `SP.dt` 改成 100 即退化为 10 Hz。

配套策略：
- **变化阈值**：listener 位置 >1e-3 m、yaw/pitch >0.5°；source 位置 >0.01 m；未变化不发。
- **in-flight 背压**：上一发未返回则跳过本拍，避免慢请求堆积。
- **心跳**：静止每 2 s 补发一次，防止内核重启/丢包造成状态漂移。
- **静默降级**：`httpRequest` 失败返回 `null`（既有约定，`ui/main.js:307-330`）→ handler 回 `{ok:false, unsupported:true}`；渲染进程连续 3 次失败即停发，不清空 3D UI、不弹错、不影响音量/切换。
- **初始同步**：布局生成后把全部节点位置发一遍；切换汇聚端后按新布局重发。

#### 2.4.3 为什么不做批量/数组

现有 JSON helper 只有"找 key → 取第一段标量"（`JsonFindNumber/JsonFindBool/JsonGetString`，`include/audiohub/http_api.hpp:40-42`、`src/http_api.cpp:218-268`），没有数组解析。批量要新写数组解析器，收益只是"少几十个 loopback 请求"（每个 <1 ms），不值得。**保持一节点一请求。**

### 2.5 步骤 5：听者联动（相机 ↔ 声场）

#### 2.5.1 模型选择：听者固定在汇聚端原点，yaw 跟随相机（已定案）

备选模型对比（`build/_plan/lead_probe` 与 `spatial_model_a.exe` 实测）：

| 模型 | 最大可达方位 | 左右差异 | 说明 |
|---|---|---|---|
| A. 相机即听者（眼位在 2.6R） | **±23.6°** | 最大 L/R 仅 5.9 dB，ITD 12.1 帧 | 环上所有节点都在相机前半球且距离 1.66–3.57R；**无法验收 ±90°/身后** |
| B+. 听者固定原点、yaw=相机 φ | **±90°** | 满量程（az=90 → 单耳 0 dB） | 转头=相机 orbit，声场随视角旋转；缩放不改变听者 → 音量不变 |

选择 B+ 的理由：①能覆盖"左右/前后"验收；②符合"听者坐在汇聚端音箱位置"的物理直觉；③相机缩放/拉近不会让整体音量跳变。

> **v1.3 变更**：听者模型由 B+ 改为**固定听者**（`yaw=0`，永远面朝屏幕上方 / -Z）；相机 orbit 只改变观察方向，不再旋转声场。原 B+ 的"转头=orbit"不再成立，理由与影响见 §7.3。

> **实施修订（v1.2）**：默认俯仰由 16.077° 改为 **40°**（`ui/scene3d.js:47` `pitchDefault: 40`）；B+ 听者模型与下节公式不变，原因与实测数字见 §6.1。

#### 2.5.2 换算公式与验证

```js
// 听者固定在原点 (0,0,0)，yaw = 相机方位角 φ；正前=(-sinφ,0,-cosφ)，正右=(cosφ,0,-sinφ)
function listenerOf (view) {
  const a = view.phiDeg * DEG
  const fwdH = [-Math.sin(a), 0, -Math.cos(a)]
  const rightH = norm(cross(fwdH, WORLD_UP))
  return { pos: [0, 0, 0], yawDeg: wrap360(view.phiDeg), pitchDeg: -view.pitchDeg, fwdH, rightH }
}

// 节点相对听者：az 0=正前、+90=右耳、-90=左耳、±180=身后；dist 为欧氏距离（音量衰减用）
function azOf (listener, p) {
  const rel = [p[0] - listener.pos[0], 0, p[2] - listener.pos[2]]
  return { azDeg: Math.atan2(dot(rel, listener.rightH), dot(rel, listener.fwdH)) / DEG,
           dist: Math.hypot(p[0], p[1], p[2]) }
}
```

实测（节点固定世界 az=90°）：

| φ（相机绕 +Y） | 相机位置 | 听者 yaw | 该节点相对 az |
|---|---|---|---|
| 0° | (0,0.72,2.50) | 0° | **+90°（右耳）** |
| 45° | (1.77,0.72,1.77) | 45° | +135° |
| 90° | (2.50,0.72,0) | 90° | **180°（身后）** |
| 180° | (0,0.72,-2.50) | 180° | **-90°（左耳，左右互换 ✔）** |
| 270° | (-2.50,0.72,0) | 270° | 0°（正前） |

- `az ≡ 世界方位 + φ` 误差 `2.8e-14`；"把节点放在听者正前"在 φ=0/90/180/270 下都投影到 hub 上方（sy≈167 < 208），相对 az=0（误差 3.2e-15）→ **屏幕上方恒为听者正前，不随 orbit 改变**。
- 缩放（滚轮）只改相机距离：φ/听者不变 → 节点 az/dist 不变（误差 <1e-9）→ **不会"一缩放声音就乱"**。
- pitch：P0 上报但不影响声像（听者仰角对左右/前后无贡献）；`listener.pitchDeg = -camera.pitchDeg`（相机俯视 = 听者低头），引擎只读取用于未来 elevation。

### 3.1 画布拾取（`ui/scene3d.js`，已验证）

```js
// 屏幕(虚拟 920x460) → y=0 水平面；拾取与拖动共用。相机 pitch>=6° 时不会退化。
function unproject (view, sx, sy, planeY) {
  const dx = (sx - CFG.CX) / view.focal
  const dy = -(sy - CFG.CY) / view.focal
  const dir = norm(add(add(mul(view.right, dx), mul(view.up, dy)), view.fwd))
  if (Math.abs(dir[1]) < 1e-6) return null
  const t = ((planeY == null ? 0 : planeY) - view.eye[1]) / dir[1]
  return t <= 0 ? null : add(view.eye, mul(dir, t))
}

// 命中测试：投影球半径 + 6px 容差；同距取更近深度；相机后方 visible=false 自然不可点。
function hitTest (items, sx, sy, slop) {
  let best = null
  for (const n of items) {
    if (!n.visible) continue
    const rPx = n.rPx + (slop == null ? 6 : slop)
    const d2 = (n.sx - sx) ** 2 + (n.sy - sy) ** 2
    if (d2 > rPx * rPx) continue
    if (!best || d2 < best.d2 || (d2 === best.d2 && n.depth < best.n.depth)) best = { n, d2 }
  }
  return best ? best.n : null
}
```

### 3.2 上报泵（`ui/renderer.js`，已落地）

```js
// 50 ms tick：listener 变化才发 + 2 s 心跳；source 只在位置变化时发；失败 3 次静默停发。
const SP = { dt: 50, epsPos: 1e-3, epsAng: 0.5, epsSrc: 0.01, heartbeat: 2000, maxFails: 3 }

function createSpatialPump (scene, hub) {
  let lastL = null, lastSent = 0, inflight = false, fails = 0, disabled = false
  const lastSrc = new Map()                       // nodeId -> [x,z,enabled]
  return function pump (now) {
    if (disabled) return
    const f = scene.spatialFrame()                // {listener:{x,y,z,yaw,pitch}, sources:[{id,x,z,enabled}], changed}
    if (!f) return

    const moved = f.sources.filter((s) => {
      const prev = lastSrc.get(s.id)
      return !prev || Math.abs(prev[0] - s.x) > SP.epsSrc || Math.abs(prev[1] - s.z) > SP.epsSrc ||
             prev[2] !== s.enabled
    })
    const listenerDue = !lastL || Math.abs(f.listener.x - lastL.x) > SP.epsPos ||
      Math.abs(f.listener.y - lastL.y) > SP.epsPos || Math.abs(f.listener.z - lastL.z) > SP.epsPos ||
      Math.abs(f.listener.yaw - lastL.yaw) > SP.epsAng || Math.abs(f.listener.pitch - lastL.pitch) > SP.epsAng

    if (inflight) return                            // 背压：上一发未返回就跳过本拍
    let req = null
    if (listenerDue && now - lastSent >= SP.dt) {
      lastSent = now; lastL = f.listener
      req = hub.setListener(f.listener)
    }
    // 位置：拖拽结束/首次布局/重连时触发；一次 tick 内按队列顺序发。
    if (moved.length && now - lastSent >= SP.dt) {
      lastSent = now
      moved.forEach((s) => { lastSrc.set(s.id, [s.x, s.z, s.enabled]) })
      const chain = req || Promise.resolve({ ok: true })
      req = chain.then(() => Promise.all(moved.map((s) => hub.setSourceSpatial(s.id, s.x, s.z, s.enabled))))
    }
    // 静止心跳：listener 每 2 s 补一发，防止内核重启后状态漂移。
    if (!req && lastL && now - lastSent >= SP.heartbeat) { lastSent = now; req = hub.setListener(lastL) }
    if (!req) return

    inflight = true
    Promise.resolve(req).then(
      (r) => { inflight = false; fails = 0; if (r && r.unsupported) { fails++; if (fails >= SP.maxFails) disabled = true } },
      () => { inflight = false; if (++fails >= SP.maxFails) disabled = true }
    )
  }
}
```

```cpp
                           const SpatialParams& params, float user_gain) {

  if (!has_target_) return;   // 未设置位置：直通，由调用方决定是否给默认位置

  const Geo geo = AnalyzePosition(target_, listener);
  const float dt = static_cast<float>(frames) / sample_rate_;
  const float k = SmoothCoef(dt, params.smooth_tau_sec);   // ≈0.0952 / 5ms 块

  float pan_l = 0.0f, pan_r = 0.0f;
  PanGains(geo.azimuth_deg, params.azimuth_boost, &pan_l, &pan_r);
  const float dist_gain = DistanceGain(geo.distance);
  const float rear = RearFactor(geo.azimuth_deg);
  const float cutoff_hz = RearCutoffHz(rear);

  const float itd_frames = ItdSeconds(geo.azimuth_deg) * sample_rate_;
  sm_delay_ += Clamp(itd_frames - sm_delay_, -params.max_delay_slew_frames, params.max_delay_slew_frames);
  sm_dist_ += (dist_gain - sm_dist_) * k;
  sm_rear_ += (rear - sm_rear_) * k;

  const float rear_gain = 1.0f - (1.0f - kRearGain) * sm_rear_;          // 正后 → 0.7
  const float raw_l = pan_l * kMonoMakeup * sm_dist_ * user_gain * rear_gain;
  const float raw_r = pan_r * kMonoMakeup * sm_dist_ * user_gain * rear_gain;
  const float target_l = gain_l_ + (raw_l - gain_l_) * k;                 // 50 ms 平滑
  const float target_r = gain_r_ + (raw_r - gain_r_) * k;
  const float dl = sm_delay_ > 0.0f ? sm_delay_ : 0.0f;                  // 远耳延时
  const float dr = sm_delay_ < 0.0f ? -sm_delay_ : 0.0f;

  const float alpha = 1.0f - std::exp(-2.0f * kPi * cutoff_hz / sample_rate_);
  for (int i = 0; i < frames; ++i) {
    hist_[0][hist_pos_] = 0.5f * (interleaved[2 * i] + interleaved[2 * i + 1]);   // 单声道化
    hist_pos_ = (hist_pos_ + 1) % kSpatialHistoryFrames;

    const float l = ReadHistory(dl);      // 分数延时（线性插值）
    const float r = ReadHistory(dr);
    const float mid = 0.5f * (l + r);
    lp_ += alpha * (mid - lp_);
    const float dull = sm_rear_ * (lp_ - mid);              // 干湿混合：越靠后越闷
    const float t = frames > 1 ? static_cast<float>(i) / static_cast<float>(frames - 1) : 1.0f;
    const float gl = gain_l_ + (target_l - gain_l_) * t;    // 块内线性过渡，避免台阶
    const float gr = gain_r_ + (target_r - gain_r_) * t;
    interleaved[2 * i] = (l + dull) * gl;
    interleaved[2 * i + 1] = (r + dull) * gr;
  }
  gain_l_ = target_l; gain_r_ = target_r; delay_l_ = dl; delay_r_ = dr;
}
```

## 7. v1.3 修订：物理房间 + 固定听者 + 大小表示远近（2026-10-26）

> 本节是**实现的最新口径**；与 §2.2/§2.5 冲突时以本节为准。C++ 空间化链路（§2.3、§3）**没有变化**，变的是"UI 把节点摆在房间哪里、听者朝哪、球画多大"。

### 7.1 需求与决策

用户原话（2026-10-26 22:00 左右）：

> "我想到是那种物理空间的位置，而不是现在这样固定前后左右。用大小来模拟远近"

澄清后的两个产品决策：

| # | 问题 | 用户选择 | 影响 |
|---|---|---|---|
| D4 | 默认摆放方式 | **物理房间中分散的默认位置，远近不一**（用球大小与距离衰减体现） | 废弃"等距圆环 + 小 n 特判"；改为 32 个黄金角槽位，半径 0.85–2.2 m 分散 |
| D5 | 听者视角 | **固定听者位置和朝向**，转动只改视角 | 听者恒在原点、yaw=0（朝屏幕上方/-Z）；相机 orbit 不再旋转声场 |

目标：

1. 节点看起来"摆在房间里"，有前后、有远近，而不是排成一个圈；
2. **近大远小**：球半径跟声学距离走（透视投影 × 距离缩放的叠加），距离文字（`x.xx m`）同步显示；
3. 听者不动：声像只由节点世界 XZ 决定——节点在 +X 即右耳、-Z 即正前、+Z 即身后；
4. 新设备入网时直接落进房间（`addDeviceToRoom` 找一个空槽/随机方位），不跳位、不叠球。

```js
function azOf (listener, p) {
  const rel = [p[0], 0, p[2]]
  return { azDeg: Math.atan2(rel[0], -rel[2]) / DEG,   // +X 右耳(+90)、-Z 正前(0)、+Z 身后(180)
           dist: Math.hypot(p[0], p[1], p[2]) }
}
```

- 相机：`phi` 只决定观察方向；`pitch∈[6,74]`、`dist∈[1.2,6.0]`，默认 `phi=0°、pitch=40°、dist=3.4`。
- 与 v1.2 的差别：v1.2 是 `listener.yaw=相机 φ`、`az = 世界方位 + φ`，转动视角会旋转声场；v1.3 转动只改变"看"，声音纹丝不动。
- 为什么这样改：用户明确要"固定听者位置和朝向"；也符合"汇聚端坐着一个人"的物理直觉，且拖动节点走多远，听感距离就是多远，不再受视角影响。
- 结果：屏幕上"节点相对 hub 的方向"与"声像方位"在默认视角下一致（+X→右耳、上→正前），但换视角后不再保证屏幕左右=耳朵左右——这是固定听者的代价，验收时以"节点在房间中的世界位置"为准，不以屏幕方向为准（见 §7.7 与 §5.3 修订）。

## 附录 B：为什么坐标不进 GRAPH 协议

1. **协议职责不同**：GRAPH 协议解决"谁在线、谁当汇聚端、音频口是谁"（`docs/GRAPH-PROTOCOL.md` §1/§3），位置是**展示/听感参数**，与入网/合并无关。
2. **合并算法不能乱**：GRAPH 的合并是"节点并集 + 远端优先"（LWW），如果加坐标就会被远端不断覆盖，导致拖动被"抢回"；除非引入"位置所有者"概念，复杂度远超收益。
3. **P0 单端权威最简单**：听者=本机汇聚端，本机 UI 就是唯一位置来源；无需一致性协议。
4. **多端一致（P1）的两条路**：
   - (a) 扩展 GRAPH 节点字段 `posX/posY/posZ` + 版本号，周期广播（~1 Hz）——只适合静态布局，**跟随相机的 yaw 10 Hz 做不到**；
   - (b) 新增 PC→hub 的 UDP 控制消息（`SPATIAL-POSE`/`SPATIAL-NODE`），适合高频跟随，Android P1 也需要它。
   两条路都只影响 P1，不影响 P0 落地。
